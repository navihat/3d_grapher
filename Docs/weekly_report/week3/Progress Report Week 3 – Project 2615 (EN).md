## 2. Review of technical activities

**Activity 1: Vuforia setup and tracking module (Duy).** Vuforia Engine 11.4.4 was imported and configured with a Basic licence. The `Tracking` module implements `ITargetOrigin` (in `Core`): `TargetOrigin` sits on the Vuforia ImageTarget, exposes the target ID, the origin transform `GraphRoot` and whether the target is tracked, and raises an event when the tracking state changes (Tracked, Extended Tracked, Lost). Other modules use the interface only, so they do not depend on Vuforia. The Main scene and a sandbox scene (`Sandbox/DuyTest`) were created, with a Vuforia device database for the worksheet.

**Activity 2: Worksheet marker v1 (Duy).** A Python script (`Worksheets/source/generate_marker.py`) generates the A4 worksheet with printed Oxy axes and a feature-rich, non-repeating border, keeping the outer 8% margin clear as Vuforia recommends. The output is `Worksheets/targets/worksheet_v1.png`. The star rating in Vuforia Target Manager was not recorded.

**Activity 3: First tracking measurements (Duy).** The worksheet was printed on matte A4 paper and tested on an Android 13 phone at 20/40/60 cm and 0°/30°/60° tilt. Recognition was stable at 20–40 cm at all angles; at 60 cm it became slow and failed at 60° in low light. Offsets between the AR axes and the printed axes were measured at the origin and four points on the axes. At review the team found that these numbers are not valid for Gate 1: the target width in Unity was still 1 instead of 0.297 m, and Extended Tracking was not enabled when the hand-occlusion column was measured. Both tables will be measured again after the fix.

**Activity 4: Learning objectives and POE exercises (Hùng).** Five measurable objectives tied to Lesson 13: identify the region (MT1); set up and compute the area S = ∫|f(x)|dx, including when f changes sign (MT2); describe the solid of revolution (MT3); explain that the cross-section is a disc of radius f(x) and set up V = π∫f(x)²dx (MT4); find and fix a wrong solution (MT5). Four exercises follow the textbook examples, each with three prediction questions, an explanation question with a rubric (correct / partial / wrong) and an integral step:

| # | Function and bounds | Textbook source | Objectives | Answer |
| --- | --- | --- | --- | --- |
| 1 | y = x³ on [0; 2], compared with triangle OAB | Example 1 | MT1, MT2 | S = 4 |
| 2 | y = sin x on [0; 2π] | Example 2 | MT1, MT2 | S = 4 (∫f = 0) |
| 3 | y = 2x − x² on [0; 2], find the error in a sample solution | Exercise 4.17 | MT3, MT4, MT5 | V = 16π/15 |
| 4 | y = √(4 − x²) on [−2; 2], half-disc → sphere | Example 8 | MT1, MT3, MT4 | V = 32π/3 |

The set was extended to cover the area of a plane region as well as volume, following the order of the textbook. Exercise 2 and Exercise 3 each use a "natural but wrong" solution (∫f instead of ∫|f|; missing square) so that the prediction is likely to be wrong and the observation resolves the conflict. Hùng also wrote a longer proposal document for the lesson (idea, objectives, exercise sequence, app flow, MVP scope, evaluation).

**Activity 5: Design thinking and wireframe in Figma (Hùng).** The Ideate part of the FigJam board maps three difficulties (complex functions are hard to picture; the content feels dry; well-known tools are not easy to access for most high-school students) to four solution directions: a visual tool, interactive parameters and viewing angles, a phone app (more flexible than a website on a computer), and only the features needed for the lesson. These lead to the concept "an AR app built together with worksheets".

![Design thinking – Ideate (Figma)](figma-design-thinking.png)

The wireframe shows the basic flow in 5 screens:

1. **Scan worksheet:** camera view with a frame and instructions to place the worksheet on a flat surface.
2. **Enter data:** after the worksheet is recognised, the student enters f(x), the bounds a and b and the axis of rotation (Ox; Oy is shown as coming later), then draws the graph.
3. **Region and prediction:** the region is shaded on the printed axes; two multiple-choice questions (what solid is formed; volume range) must be submitted before the solid is shown.
4. **AR solid and cross-section:** tabs Region / Solid / Cross-section; a slider moves the cross-section along x and shows its radius; the region can be split into 4 → 8 slices.
5. **Set up the integral:** the student fills in V = ∫ₐᵇ [ … ] dx; the app points to the wrong step (for example the radius of the cross-section) with a hint button and counts hints and attempts.

## 4. Developed code review

### Algorithmic development

- **Origin from the target (implemented):** the graph is a child of `GraphRoot` under the ImageTarget. With the target width set to the real printed width (0.297 m) and 1 unit = 1 cm, a point (x, y) on the paper maps to `GraphRoot` local position (x, 0, y) scaled to centimetres, so the drawn graph lies on the printed axes. The width fix is still pending.
- **Tracking state (implemented):** Vuforia statuses are mapped to three states: `TRACKED` → Tracked, `EXTENDED_TRACKED` → Extended Tracked, `NO_POSE`/`LIMITED` → Lost. The exercise module will use this to pause the activity and show a message when the worksheet is lost.
- **Marker generation (implemented):** the script draws the axes in the centre and fills the border with asymmetric shapes with many sharp corners, the kind of features Vuforia rates highly; the outer 8% is left empty.
- **Grading with step hints (designed, from the wireframe and exercises):** the submitted integrand is compared with f(x)² and with typical wrong forms (f(x), missing π, wrong bounds); a match tells the student which step is wrong.
